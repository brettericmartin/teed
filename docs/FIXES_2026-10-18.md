# Fixes — 2026-10-18 (`teed-fixes-2026-10-18`)

Defect sweep after the 2026-10-17 live review. Each section is one commit on the
branch. Nothing here touches the database or runs a migration; the owner merges.

Verification: `npx tsc --noEmit` is clean for app code (the pre-existing errors in
`tests/unit/*.test.ts`, `tests/e2e/12-mobile-layout-view.spec.ts` and
`packages/mcp-server/**` — a missing `@modelcontextprotocol/sdk` install — are
untouched). `npx eslint` on every changed file reports only pre-existing findings
(`no-explicit-any`, unescaped quotes, a `setMounted` in an effect).

## 1. Remove unauthenticated debug / migration routes

Deleted:

- `app/api/migrations/promo-codes/route.ts` — ran SQL through an `exec_sql` RPC that
  does not exist in the database; anyone could call it.
- `app/api/auth/oauth/debug/route.ts` — echoed OAuth configuration.
- `app/api/ai-test/route.ts` — anonymous paid OpenAI call.

`MVP_BUILD_GUIDE.md` no longer points at `/api/ai-test`.

## 2. Auth guards on paid and admin endpoints

`requireAuth` (`lib/apiAuth.ts`) now runs before any work in POST of:

- `app/api/bulk-text/process/route.ts`
- `app/api/ai/{analyze-product-url, detect-objects, enhance-search-query, enrich-item,
  enrich-product-details, enrich-products-v2, generate-fun-facts, identify-from-image,
  identify-products-v2, validate-match, store-visual-correction, find-product-image,
  extract-product-images, store-correction}/route.ts`
- `app/api/analytics/corrections/route.ts`, `app/api/analytics/identification/route.ts`

`getAdminUser` (`lib/adminAuth.ts`) guards POST `app/api/discovery/run/route.ts`,
POST `app/api/discovery/gaps/route.ts`, and GET on the two analytics routes.

Handlers with a declared `NextResponse<T>` return the 401 in their own response
shape (`{ success: false, error: 'Unauthorized' }`, plus `learned: false` for
store-correction) because the helper's generic 401 does not type-check against them.
Routes that already had a module-level service-role `supabase` client use
`authClient` for the user-session client so the insert path is unchanged.

## 3. PostgREST embed hints (PGRST201)

`bags` has two relationships to `bag_items` (`bag_items.bag_id` and
`bags.hero_item_id`), so every un-hinted embed failed with "more than one
relationship". Added `bag_items!bag_items_bag_id_fkey(...)` /
`bags!bag_items_bag_id_fkey!inner(...)` in:

- `app/api/v1/bags/popular/route.ts` (also returns `detail`/`code` from PostgREST when
  `NODE_ENV !== 'production'`), `app/api/v1/products/search/route.ts`,
  `app/api/v1/brands/route.ts`
- `app/api/mcp/route.ts` (5 embeds), `app/api/gpt/items/[id]/route.ts`,
  `app/api/gpt/search/route.ts`, `app/api/admin/items/route.ts`,
  `app/api/admin/content-ideas/[id]/team-generate/route.ts`,
  `app/api/ai/generate-why-chosen/route.ts`
- `app/api/og/bag/[handle]/[code]/route.tsx`, `app/api/export/[code]/route.ts`
- `app/embed/bag/[handle]/[code]/page.tsx`, `app/embed/profile/[handle]/page.tsx`
- `app/u/[handle]/feed.xml/route.ts`, `app/u/[handle]/[code]/feed.xml/route.ts`
- `lib/ideas/index.ts`, `lib/analyzer/index.ts`, `lib/products/resolveProduct.ts`

`bag_collection_items -> bags` embeds in the collections routes are a different
edge and were left alone.

## 9. Owner-scoped mutations under `/api/bags/[code]/**`

Added `.eq('owner_id', user.id)` to the bag lookup (the pattern from
`complete/route.ts`) in: `route.ts` PUT/DELETE, `bulk-links` POST, `bulk-links/save`
POST, `bulk-text/save` POST, `cover-photo` POST/DELETE, `history` POST,
`history/[entryId]` PATCH, `items/from-url` POST, `items` PATCH, `related`
POST/DELETE, `sections` POST, `sections/[sectionId]` PUT/DELETE. Another user's bag
now 404s on a mutating request instead of being fetched and then rejected. Public
GETs, `copy` (reads a source bag you do not own by design) and `save` (writes
`saved_bags`, not `bags`) are unchanged.

## Deliberately NOT done

- **`force-dynamic` in `app/layout.tsx`** — removing it changes caching for every
  route; needs its own test pass.
- **Invite-code enumeration** — the fix is an RPC / RLS change, which is a database
  change; out of scope for a code-only branch.
- **Gating `/api/auth/signup`** — product decision (open vs. invite-only signup), not
  a defect.
- **Featured bags from `bags.is_featured`** — 3 bags are flagged but the surfaces
  that would read it are not built; wiring it is a feature.
- **SSRF DNS resolution** in the URL-fetching routes — needs an allow/deny design,
  not a one-line patch.
- **Broken storage photo filenames** — data (object keys in Supabase Storage), not
  code. `ItemImage` now degrades gracefully, but the files themselves need a data fix.
- The `MasonryView` unescaped-quote and `ProfileGridLayout` setState-in-effect lint
  findings pre-date this branch and were not touched.
